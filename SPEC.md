# Encore Builder — Build Specification

> This is a complete, self-contained specification for a client-only website-builder
> prototype. Build exactly what is described here. Every literal value (hex, px, string,
> ratio) is normative — do not "improve", round, or substitute design tokens.
>
> Reference designs live in **`docs/feedback-reference/`**:
> `template-1-retro.png` … `template-5-pop.png` (template previews) and
> `header-layout-1.png` … `header-layout-6.png` (the six header designs). They are the
> visual source of truth for §6 and §10.2; the prose there resolves tokens, spacing and
> behaviour. Where image and prose disagree, follow the image.

---

## 1. What you are building

**Encore Builder** — a single-page, client-only prototype of a website builder for
musicians and DJs. A user picks a visual **template**, chooses whether to start from a
filled-in example or an empty page, then edits a page made of stacked **sections** —
adding, removing, reordering, swapping layouts, recolouring and editing copy — while
seeing a live, fully re-skinned preview.

It is a **demo**: nothing persists, nothing is sent to a server, "Publish" only shows a
toast. All content is demo content for a fictional DJ, "Kai Mercer".

Three sequential stages:

1. **`template`** — choose one of 5 templates (dark full-screen gallery).
2. **`start`** — choose **Theme Example** (populated page) or **Blank** (header + footer).
3. **`editor`** — the builder proper (light chrome, sidebar + canvas).

## 2. Tech stack & project setup

- **React 18.3** — function components and hooks only. No router, no state library, no
  TypeScript, no tests.
- **Vite 6** with `@vitejs/plugin-react`.
- **Tailwind CSS 4** via `@tailwindcss/vite` — CSS-first config, no `tailwind.config.js`,
  no PostCSS config.
- **shadcn/ui** — style `new-york`, base colour `stone`, CSS variables on (§3.4).
  Components are copied into `src/components/ui/`, not installed as a dependency.
- **`lucide-react`** for all icons, in the chrome **and** inside rendered sections (§3.6).
- **`vite-plugin-singlefile` 2.3** for a second build target that inlines all JS and CSS
  into one `index.html` runnable from `file://` with no server.

**Division of labour — read this before writing any component.** shadcn covers the builder
chrome only (§6–§9): top bar, sidebar, edit panel, drawer, sheets, toast. The section
renderer (§10) **cannot** use it: sections are painted with arbitrary hex values chosen at
runtime from a colour set, plus six derived `rgba()` values, and a static utility class
cannot express `background: s.bg` where `s.bg` is `#7A58A7` picked at runtime. §10 stays
inline-styled. Only its icons come from lucide, which inherits `currentColor` and so stays
theme-driven.

**Sizing precedence.** Where this spec gives an exact px value and a shadcn component's
default disagrees, **the spec wins** — override the component. shadcn contributes
behaviour, focus management, keyboard interaction and ARIA; it does not get to redefine
the visual design.

## 3. Styling foundation (`src/index.css` + shadcn)

### 3.1 Base

Tailwind v4 is configured from CSS. The file begins:

```css
@import "tailwindcss";
@import "tw-animate-css";

@custom-variant dark (&:is(.dark *));

/* §3.4 supplies @theme inline, :root and .dark */
```

Then the app's own base layer:

```css
:root { color-scheme: light; }
html { -webkit-font-smoothing: antialiased; -moz-osx-font-smoothing: grayscale; }
html, body { margin: 0; padding: 0; background: #e9e7e1; }
* { box-sizing: border-box; }
a { color: inherit; text-decoration: none; }
a:hover { opacity: .72; }
input::placeholder, textarea::placeholder { color: inherit; opacity: .45; }
```

Tailwind v4 has no Preflight `border-color` reset compatible with v3 defaults; shadcn's

### 3.3 Hover utility classes

Chrome hover states come from Tailwind utilities on the §3.4 tokens — `hover:bg-accent`,
`hover:bg-muted`, `hover:border-foreground`, and so on. Only four hand-written classes
survive, because each depends on something the token layer cannot express.

```css
/* Chrome — transforms and a multi-property card lift. */
.hv-scale12:hover { transform: scale(1.12); }
.hv-scale15:hover { transform: scale(1.15); }
.hv-lift:hover    { transform: translateY(-5px); border-color:#4a4a42; box-shadow:0 20px 40px rgba(0,0,0,.4); }

/* Sections — theme-aware, reading custom properties set per section at runtime. */
.hv-indent:hover { padding-left: 12px !important; }
.hv-acbord:hover { border-color: var(--ac) !important; }
.hv-acfill:hover { background: var(--ac) !important; color: var(--acFg) !important; border-color: var(--ac) !important; }
```

`--ac` / `--acFg` are set as inline custom properties on each rendered section root (§10).
The three section classes must stay CSS — a utility class cannot reference a value chosen
at runtime.

### 3.4 Design tokens

Base colour **stone** — the chrome palette is warm (R > G > B throughout), and stone is the
only warm option among slate/gray/zinc/neutral/stone. Two anchors show the fit:
spec ink `#1B1A17` vs `stone-900 #1c1917`; spec sidebar `#F8F7F4` vs `stone-100 #f5f5f4`.

Stone gets ~90% of the way; the design runs slightly more olive than stone's taupe, so
**overwrite the generated values with these exact hexes**. They are the same values used
throughout §6–§9, so the two never drift.

## 4. Static data module (`src/builder/data.js`)

Pure data plus four helpers. Reproduce every value exactly.

### 4.1 `THEMES` — 5 templates

Each entry: `{ name, sub, display, label, body, casing, dls, radius, radiusSm, btnR, bw, sets, tags }`.

- `display` / `label` / `body` — CSS font-family strings. `label` is the caps face used for
  nav, eyebrows, buttons and chips; every theme except Retro sets it to its own `body`.
- `bw` — border width. Retro is `2px` (the §10.2 reference); the others keep `1.5px`.
- `casing` — `'lower' | 'upper' | 'title'`, applied to headline-ish strings via `caseText`.
- `dls` — display letter-spacing.
- `radius` / `radiusSm` / `btnR` — card, small-element and button radii.
- `sets` — **exactly five** `[background, accent, text]` hex triples (§4.2).
- `tags` — chip palette, cycled with `%`.

| Theme | `sub` | `display` | `body` | `casing` | `dls` | radius / radiusSm / btnR |
|---|---|---|---|---|---|---|
| Retro | `Alfa Slab One · warm 70s` | `'Alfa Slab One', serif` | `'Inter', sans-serif` | title | `0px` | 20px / 14px / 999px |
| Lime | `Bebas Neue · dark acid` | `'Bebas Neue', sans-serif` | `'Archivo', sans-serif` | upper | `0.02em` | 6px / 4px / 4px |

### 5.2 Single state object

One `useState` holding everything, updated through a `patch(partialOrFn)` helper:

```js
{
  stage: 'template' | 'start' | 'editor',
  theme: number,                  // index into THEMES
  sections: Section[],            // page model
  device: 'desktop' | 'tablet' | 'mobile',
  drawer: null | 'add' | 'swap',
  drawerCat: null | categoryId,
  swapFor: null | sectionId,
  menuFor: null | sectionId,      // ⋯ menu open in a sidebar row
  setRowFor: null | sectionId,    // inline colour-set row in a sidebar row
  canvasSetFor: null | sectionId, // colour-set strip in the canvas overlay toolbar
  hoverId: null | sectionId,
  selectedId: null | sectionId,
  toast: '',
  sheet: null | 'sections' | 'theme',  // mobile bottom sheets
  editSheet: false,               // mobile edit bottom sheet
}
```

`Section = { id: number, cat: categoryId, arch: number, set: number, c: {} }` where `c`
holds only user-overridden field values and `set` is always `0..4`.

Ids come from a `useRef(100)` counter, pre-incremented (`++uidRef.current`).

For an `image` field, `c[key]` holds a **data URL string** (§8.6), so a section stays a
plain serialisable object.

### 5.3 Boot logic

```js

if (ti >= 0) → { stage:'editor',   theme: ti, sections: buildPage(EXAMPLE_PAGE) }
else         → { stage:'template', theme: 0,  sections: [] }
```

`buildPage(defs)` maps `[cat, arch, set]` triples to `Section` objects with fresh ids.

### 5.4 Section constraints

Three invariants must hold at all times. Enforce them in the mutation layer **and** reflect
them in the UI by disabling the controls that would violate them — never let a user click
something that silently does nothing.

1. **Header is always `sections[0]`. Footer is always last.** Neither can be moved. Their
   ▲/▼ and canvas ↑/↓ controls render in the disabled colour and are inert.
2. **Header and footer are mandatory.** Neither can be deleted. Omit `✕ Delete` from their
   row menu, the `Delete` button from their edit-panel footer, and `✕` from their canvas
   toolbar.
3. **Each category may appear at most once.** In the Add drawer, a category already on the
   page is shown disabled. There is no Duplicate action anywhere in the app.

```js
function canMove(sections, id, dir) {
  const i = sections.findIndex(s => s.id === id)
  const sec = sections[i]
  if (sec.cat === 'header' || sec.cat === 'footer') return false
  const j = i + dir
  return j >= 1 && j <= sections.length - 2   // stay between header and footer
}
```

**Axis A — builder chrome breakpoint.** `useIsMobile()` subscribes to

**Axis B — canvas device preview.** `SIZES` supplies sizing tokens injected into every

### 5.6 Core mutations

| Action | Behaviour |
|---|---|
| `move(id, ±1)` | swap with neighbour; no-op when `canMove` is false |
| `toast(msg)` | set `toast`, clear previous timer, auto-clear after **2400 ms** |
| `setContent(id,k,v)` | shallow-merge into that section's `c` |
| `setSection(id, patch)` | merge into the section **and** clear `setRowFor` |
| `closeAll()` | clears `menuFor`, `setRowFor`, `canvasSetFor`, `selectedId` — wired to the editor root's `onClick` |
| delete | rejected for header/footer; otherwise filter out; if it was selected, clear `selectedId` and `editSheet` |
| add section | rejected if the category is already present; otherwise inserted **immediately before the footer**; `set = (sections.length - 1) % 5`; toast `"{Category} added"` |
| publish | toast only: `'Published to kaimercer.encore.site (demo)'` |

**Event isolation:** a `stopE(e)` helper calls `e.stopPropagation()` and is applied to
virtually every interactive handler and to modal/drawer/sheet panels, because the editor
root closes menus on any bubbled click.

### 5.7 View-model construction (`makeVm(sec, i, arr)`)

Every section is projected into a flat, fully-resolved view-model **before** rendering.
`EncoreSection` receives only precomputed values and does zero colour maths.

```
acFg   = contrast(ac)
muted  = rgba(tx, .64)
line   = rgba(tx, .16)
line2  = rgba(tx, .40)
soft   = rgba(tx, .08)
soft2  = rgba(tx, .18)
v0…v5  = (sec.arch % NVAR[cat]) === 0…5
```

## 10. `EncoreSection.jsx` — the section renderer

Purely presentational: `function EncoreSection({ s })`. Root element:

```jsx
<div style={{
  background: s.bg, color: s.tx, fontFamily: s.body, padding: s.pad,
  transition: 'background-color .45s ease, color .45s ease',
  '--ac': s.ac, '--acFg': s.acFg,
}}>
```

The custom properties power `.hv-acbord` / `.hv-acfill`. The 450 ms colour transition is
what makes theme and colour-set switching feel like a cross-fade — keep it.

**This file uses no shadcn components and no Tailwind utility classes** — every value is
inline, because backgrounds, accents and text are arbitrary hexes resolved at runtime
(§2). It does use `lucide-react`: icons here inherit `currentColor`, so they stay
theme-driven, and each takes the px size given below rather than a `size-*` class.

Icons appearing in sections: `Play` (media, video, audio), `SkipBack` / `SkipForward`
(media transport), `Check` (pricing feature ticks), `ChevronLeft` / `ChevronRight`
(calendar month nav), `ArrowRight` (header CTAs), `ArrowUpRight` (seal badge), `Star`
(header layout 5 stats), `Upload` (image placeholders, where shown).

Two marks stay typographic: the `“` in testimonials and the `●` kicker bullet (§3.6).

## 12. Scope boundaries — intentionally not built

These are deliberate limits of this release. Do not "fix" them.

1. **No persistence.** Reload loses everything, including uploaded images. No localStorage,
   no URL state, no undo/redo.
2. **No drag-and-drop reordering** despite the `GripVertical` handle affordance.
   Reordering is via the arrows.
3. **Layout folding for the 13 non-header categories** — more layout numbers are offered
   than there are distinct designs (§4.4). The header is exempt.
4. **Generic drawer thumbnails for non-header categories** (`arch % 3`), decorative and
   unrelated to the actual layout. The header's are real.
5. **No real media beyond the header photo** — audio, video and the map are coloured
   placeholder blocks; play buttons, transport controls, progress bars and the calendar's
   `‹ ›` are inert.
6. **The rendered site's forms do not submit**; its CTAs are `<span>`s, not `<button>`s —
   they are demo affordances inside the preview, not real controls. This applies to §10
   only; the **builder chrome uses real, accessible controls** (item 7).
7. **Accessibility is scoped to the chrome.** Radix, via shadcn, gives the builder proper
   focus management, keyboard navigation, dismiss handling and ARIA — take it rather than
   re-implementing. The rendered preview in §10 is deliberately not accessible: it is a
   picture of a website, not a website. Icon-only chrome controls use `tooltip`, not bare
   `title`. The seal badge honours `prefers-reduced-motion`.
8. **Content is hardcoded** to the "Kai Mercer" demo persona. `artistName` is a prop, but
   every default string, email, city and price is fixed data.
9. **Two styling systems, deliberately.** Tailwind utilities and shadcn components for the
   chrome (§6–§9); inline `style={{}}` objects for the section renderer (§10), which is
   painted from runtime hex values a static utility class cannot express. Do not try to
   unify them.
10. **No shadcn inside `EncoreSection.jsx`** — only `lucide-react`.
11. **Single monolithic state object** with a `patch()` reducer-lite. `EncoreBuilder.jsx`
    is intentionally not decomposed beyond `SectionRow` and `EditPanel`; the bottom-sheet
    wrapper is now shadcn's `drawer` rather than a hand-rolled component.
12. **Templates 2–5 are visually unfinished** — they render flat-colour sections and the
    3-layout flat header family. This is scoped, not an oversight.
